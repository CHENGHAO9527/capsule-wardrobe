穿搭口径
和模型无关 —— 它决定引擎怎么判"今天这套够不够暖"

用的是「26℃穿衣法则」（人民日报 / 科普中国都在用的那条）：
当日气温 + 衣物保暖值之和 = 体感舒适温度
每件衣服的保暖值在「录入」页的改字段里（T恤 1℃、卫衣 4℃、羽绒服 9℃…）， 裤子鞋子不参与加总 —— 下半身只影响好不好看。

这个数越大，要求越高：调到 26℃ 就是法则原文（那是标给儿童的）， 更冷的日子会直接排不出搭配；调到 21℃ 更宽松。 它同时决定"你的衣橱最冷能穿到几度"。

1 选服务商

选完会自动填好接口地址和模型名。
推荐 DeepSeek：模型名填 deepseek-flash（模型版本 V4.1-Flash，原生支持看图）。 去 platform.deepseek.com 充值后建一个 API Key 粘进来即可。一个 Key 同时管识别和搭配排序，不用配两个服务商。

想一分钱不花也可以用「智谱 GLM-4V」，glm-4v-flash 有免费额度。
只存在你这台电脑的 data/vision.json 里，不上传任何地方。

2 确认参数
一般不用改，选完服务商就自动填好了

识别一张图大约 3–15 秒。本地 Ollama 慢，可以调到 180。
DeepSeek 必须勾上。它的思考模式默认打开、强度还是 high —— 模型会先把 token 花在一段思维链上（放在 reasoning_content 里），回答正文 content 就可能是空的。实测：不勾有 4/19 张图返回空，勾上 19/19 全过。 分类这种任务本来也不需要思考，关掉更快更省。 其他服务商没有这个参数，勾了也不会发出去。

3 保存并测试

接了模型之后，哪些事会变

✓
录入不用点槽位了。上传照片自动填好品类、正式度、厚度、温度区间、领型、材质、版型、图案。
✓
今日搭配有了审美排序。硬规则算出的候选里，由模型挑出最好看的那套并给一句理由。
✗
颜色仍然由本地测量，不交给模型。模型的色值会随打光变化、不可复现，而颜色决定撞色规则，错一个值会污染之后所有判断。
✗
搭配不会由模型生成。所有组合都是硬规则从你衣橱里枚举出来的 —— 让它生成，它就会推荐你根本没有的衣服。

不接模型会怎样

完全能用。录入时每件点一下槽位，其余字段按品类默认值自动填；今日搭配走本地排序。 模型是加速器，不是必需品 —— 识别失败时也会自动退回这个模式，不会卡住录入。

花钱吗

几乎不花。以 DeepSeek 为例：单张图最多算 1024 个 token，空闲时段输入 1 元 / 百万 token， 识别一件衣服约 0.2 分钱；输出按 4 元 / 百万算，一次识别也就几厘。

按 80 件衣服的初始录入算，总共不到两毛钱；之后每天几次搭配排序，一年几毛钱。 而且周末和工作日晚上（非 9:00–12:00、14:00–18:00）价格再减半。

真正的成本是你的时间，不是 API 调用。
