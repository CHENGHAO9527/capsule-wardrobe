# 衣物图片标准化方案

## 为什么必须做

三个理由，按重要性排序：

1. **色彩是搭配的核心变量。** 判断"这两件能不能搭"，本质是判断颜色关系。一张暖黄光下拍的、一张冷白光下拍的，同一个颜色会得到两个不同的 Hex 值。模型会被光线骗，你也会。
2. **视觉识别的准确率依赖一致性。** 品类、图案、材质识别都受背景和角度干扰。白底平铺的识别率远高于床上乱拍。
3. **一致性决定你会不会每天打开它。** 200 张风格各异的照片是二手市场列表，不是衣橱。浏览体验直接决定使用频率。

## 三层处理

### L0 拍摄规范（人工，一次性，收益最大）

这层不用写代码，但决定了后两层的上限。

**通用要求**

| 项 | 要求 |
|---|---|
| 背景 | 纯色（白 / 浅灰），无花纹、无杂物 |
| 光线 | 白天窗边散射光；禁直射阳光、禁闪光灯、禁室内黄光灯 |
| 角度 | 手机固定高度（书架夹持），镜头垂直向下 |
| 构图 | 衣服占画面 80%，四周留白 |
| 白平衡锚点 | 画面边缘放一张纯白 A4 纸，后期校色参照 |
| 批次 | 一次拍完一批（20 件以上），不要分多次不同光线拍 |

**按品类的标准姿势**

| 品类 | 姿势 |
|---|---|
| 上衣 / 外套 | 平铺正面，扣好拉好，袖子自然外展 15° |
| 裤装 | 侧缝对折，或垂直悬挂（裆部折线居中） |
| 裙装 | 平铺正面，腰头在上，裙摆放平 |
| 鞋 | 外侧 45° 俯视 |
| 包 / 配饰 | 正面平铺 |

**不要用穿着照。** 穿着照有姿态、体型、环境光三重干扰，抠图会切到人体，色彩失真最大。如果某件只能拍穿着照，单独存进 `img_worn` 字段，不进标准图管线。

### L1 几何归一化（本地自动）

| 步骤 | 做法 |
|---|---|
| 抠图 | `rembg`（U²-Net），本地 CPU 3–8 秒/件，零成本 |
| 背景 | 纯白 #FFFFFF |
| 画布 | 1080 × 1080 方图 |
| 留白 | 主体长边占画布 85%，四面等边距 |
| 阴影 | 底部加极浅椭圆投影（提升质感，可选） |
| 失败兜底 | 抠图置信度低于阈值 → 标记待人工，不自动通过 |

### L2 光学归一化（本地自动）

| 步骤 | 做法 |
|---|---|
| 白平衡 | 用画面里的 A4 纸做参考，校到纯白，全图同步偏移 |
| 亮度 | 按主体区域平均亮度归一化到目标区间 |
| 饱和 | **不做**。允许轻度色阶统一，禁止加饱和度或滤镜 |
| 主色提取 | 去背景后的主体区域做颜色聚类，取占比最高的簇 |
| 中性色判定 | 饱和度 < 0.15 且明度 0.2–0.9 → 判为中性色 |

主色必须在 L2 之后提取。在原始照片上取色，取到的是"当时的光"，不是衣服的颜色。

### L3 输出（四种用途）

| 文件 | 规格 | 用途 |
|---|---|---|
| `img_raw` | 原图 | 永久归档。标准化会丢材质纹理，需回头对账时用 |
| `img_display` | 1080×1080 webp，白底 | 界面卡片、衣橱地图 |
| `img_llm` | 512×512 jpg，质量 80 | 发给大模型。图片按 token 计价，这步直接省钱 |
| `img_mask` | 去背景透明 PNG | 拼图预览、抠图重做 |

## 禁止区

**不要用生成式 AI 重绘衣服。**

把用户照片"美化"成商品图风格很诱人，但生成模型会篡改颜色、图案细节、材质纹理和版型比例。结果是你拿着标准图搭配，实物对不上——整个 App 的信任基础塌掉。

能统一的是背景、几何、光线。不能动的是衣服本身。

## 附加价值：拼图预览

有了 `img_mask`，可以把一套搭配的单品按穿着位置合成一张虚拟平铺图：

- 上装居中偏上
- 下装居中偏下
- 外套叠在上装两侧
- 鞋在底部

这不是真实试穿，但足以让你和模型一眼判断色系是否和谐。纯本地 Pillow 合成，毫秒级，零成本。

附带好处：**避免把真实穿搭照发给第三方 API**，隐私风险大幅下降。

## 工作量估算

| 环节 | 耗时 |
|---|---|
| 拍摄 80 件（L0） | 2–3 小时（一次性，可分两个下午） |
| 批量处理（L1–L3） | 15 分钟（机器跑，人等着） |
| 人工纠错 | 1–2 小时（抠图失败、主色误判） |
| **总计** | **半天到一天，一次性** |
